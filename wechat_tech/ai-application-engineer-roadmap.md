# AI应用工程师学习路线图

这份路线图按岗位要求来设计，目标不是学一堆概念，而是 6 个月后能拿出可讲、可演示、可写进简历的项目。

## 一、AI应用工程师核心技能点地图

### 1. 后端工程基础

AI 应用工程师首先还是工程师。你需要把模型能力做成服务，而不是只会跑 demo。

核心技能：

1. Python
2. FastAPI
3. MySQL / PostgreSQL
4. Redis
5. Docker
6. Linux

### 2. 大模型应用基础

要懂 Token、上下文窗口、Prompt、结构化输出、Function Calling、Embedding，以及模型常见问题。

核心技能：

1. Prompt 设计
2. Structured Output
3. Function Calling
4. Embedding
5. 幻觉与约束

### 3. RAG 与知识库

重点不是知道名词，而是能搭完整链路：文档处理、切块、召回、重排、生成、引用。

核心技能：

1. Chunking
2. 向量检索
3. 重排
4. 引用来源
5. 多轮上下文

### 4. Agent 与工作流

岗位要的是“会执行任务的系统”，不是普通聊天页面。

核心技能：

1. Tool Calling
2. ReAct
3. LangGraph
4. Memory
5. Workflow

### 5. 工程化与平台化

高薪部分通常不在“会用模型”，而在“能让系统稳定跑起来”。

核心技能：

1. 权限
2. 日志
3. 监控
4. 限流
5. 成本控制
6. 任务队列

### 6. 评测与持续优化

你不只是要做出来，还要知道它是不是好、为什么不好、怎么改。

核心技能：

1. Benchmark
2. 测试集
3. LLM-as-a-Judge
4. A/B 测试
5. 回归评测

## 二、六个月阶段目标

### 第 1 个月：后端工程打底

目标：把自己从“能写脚本”升级成“能写服务”。

1. 掌握 Python 工程化写法
2. 能用 FastAPI 写接口服务
3. 会接数据库、缓存和日志
4. 会用 Docker 跑项目

### 第 2 个月：大模型应用基础

目标：看懂应用层原理，知道 Prompt、Tool Calling 和 RAG 是怎么连起来的。

1. 理解 LLM 调用和结构化输出
2. 会做简单工具调用 demo
3. 完成最小知识库问答原型

### 第 3 个月：RAG 项目落地

目标：做出企业知识库问答系统 V1。

1. 文档导入与切块
2. 向量检索和引用来源
3. 回答生成与无答案兜底

### 第 4 个月：Agent 项目落地

目标：做出能执行任务的 Agent。

1. 手写工具调用 Agent
2. 状态记录和失败重试
3. 接入简单工作流框架

### 第 5 个月：平台化和稳定性

目标：把 demo 做成“像产品”的系统。

1. 多用户和权限模型
2. 异步任务系统
3. 日志、缓存、调用统计

### 第 6 个月：评测和求职准备

目标：让项目可量化、可讲述、可面试。

1. 建立评测集和对比实验
2. 整理项目架构和技术选型
3. 准备简历和面试讲稿

## 四、6 个月后至少应该有的 3 个项目

### 项目 1：企业知识库问答系统

用来证明你会 RAG 全链路：

1. 文档解析
2. 切块
3. 召回
4. 重排
5. 生成
6. 引用来源
7. 评测
8. 兜底策略

### 项目 2：带工具调用的 Agent 应用

用来证明你真的会做任务执行型系统：

1. 至少接入 2 到 3 个工具
2. 有任务轨迹日志
3. 有状态和错误处理

### 项目 3：AI 内容生产流水线

这和你当前在做的科技日报项目很接近，适合作为业务化案例：

1. 定时抓取和结构化清洗
2. Prompt 渲染和模型生成
3. 日志、产物和失败排查链路

---

## 五、执行建议

1. 每周必须有代码产物，不要只看教程
2. 每个月必须沉淀一个阶段版本
3. 不要先卷底层训练，先把应用工程能力做扎实
4. 项目比零散知识更值钱

最务实的策略不是把所有新框架都学一遍，而是先用 6 个月做出 3 个能站得住的项目，再反向补你在项目里暴露出来的短板。
